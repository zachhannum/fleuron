fleuron reads the CSS a book needs. The pipeline honours everything on this page. A selector, property or at-rule outside it becomes a warning naming the line and column it was written at, and the run continues, so one rule the engine cannot read leaves the rest of the sheet in force.

Every stylesheet below parses. A rule pasted from here into the editor beside the page sets the chapter again.

## The defaults

The engine parses a built-in sheet before any sheet handed to it, so a book with no CSS at all is already a trade paperback. The sheet is 6×9 inches, with mirrored margins and the folio bottom centre. The text is the [bundled serif](library/fonts.md) at 11 points over a 1.4 line height, ranged left and unhyphenated. Paragraphs indent after the first, quotations set in from the measure, and a thematic break is a centred ornament. A chapter opens on a recto, with its heading held to the paragraph under it.

[The built-in sheet](#the-built-in-sheet) at the foot of this page is the whole of it. Author CSS cascades over it whatever the specificity of the rule being replaced, so `p { text-indent: 0 }` beats the built-in `p + p` rule.

An author sheet overrides as much of that as it names:

```css
@page {
  size: a5;
  margin: 16mm 14mm 18mm 16mm;
}

book {
  font-size: 10pt;
  text-align: justify;
  hyphens: auto;
}
```

## The page

`@page` sets the sheet: its trim, its margins, its columns, and the boxes in the margins a running head or a folio paints into.

{/* generated: page-grammar */}

```css
@page <name>? [ :first | :blank | :left | :right ]* {
  size: <length>{1,2} | <page-size> [ portrait | landscape ]?;
  margin: [ <length> | <percentage> ]{1,4};
  margin-top: <length> | <percentage>;
  margin-right: <length> | <percentage>;
  margin-bottom: <length> | <percentage>;
  margin-left: <length> | <percentage>;
  column-count: auto | <integer>;
  column-width: auto | <length>;
  column-gap: normal | <length>;
  column-rule-width: <length> | thin | medium | thick;
  column-rule-style: none | solid;
  @<margin-box> {
    content: none | <string> | counter(page) | counter(page, <counter-style>) | string(<name>);
    /* text properties */
  }
}
```

{/* end generated */}

### Size and margins

`size` takes two lengths, width then height, one length for a square page, or a named sheet.

{/* generated: page-sizes */}

`<page-size>` is `a3`, `a4`, `a5`, `b4`, `b5`, `letter`, `legal` and `ledger`, portrait unless `landscape` follows.

{/* end generated */}

`margin` takes a one-to-four value shorthand, and there is a longhand per edge. What the margins leave is the content box, and the width of that box is the measure: the width every line of prose breaks to.

```css
@page {
  size: 5.5in 8.5in;
  margin: 0.7in 0.6in 0.8in 0.7in;
}
```

### Which pages a rule selects

`@page` with nothing after it sets every page. A selector narrows it:

| selector | the pages it selects |
|---|---|
| `:left` | versos, the left-hand page of a spread |
| `:right` | rectos |
| `:first` | the page a page group opens on |
| `:blank` | a page inserted to square the sheet |

A page group begins wherever a section opens a page, so `:first` selects a chapter's opening page rather than only the book's. `recto` and `verso` are the book's names for right and left, and `break-before` takes them too.

A rule for each side mirrors the margins across the spread:

```css
@page :left {
  margin-left: 0.6in;
  margin-right: 0.7in;
}

@page :right {
  margin-left: 0.7in;
  margin-right: 0.6in;
}
```

`page: <name>` on an element names the pages its content falls on, and `@page <name>` selects them. The built-in sheet names a section's pages `chapter`, which is how `@page chapter:first` reaches a chapter opening and nothing else:

```css
section.front { page: front }

@page front {
  @bottom-center { content: counter(page, lower-roman) }
}
```

Page selectors cascade like any other rule: origin first, then specificity, then source order. The name outweighs `:first` and `:blank`, which outweigh `:left` and `:right`.

### Running heads

A margin box is a rule inside `@page`, and `content` is what it paints. Every text property parses in one too.

{/* generated: margin-boxes */}

The margin boxes that paint are `@top-left`, `@top-center`, `@top-right`, `@bottom-left`, `@bottom-center` and `@bottom-right`. `@top-left-corner`, `@top-right-corner`, `@left-top`, `@left-middle`, `@left-bottom`, `@right-top`, `@right-middle`, `@right-bottom`, `@bottom-left-corner` and `@bottom-right-corner` parse and paint nothing.

{/* end generated */}

| `content` | paints |
|---|---|
| `"Pride and Prejudice"` | the string |
| `counter(page)` | the folio |
| `counter(page, lower-roman)` | the folio in another counter style |
| `string(chapter)` | a running string |
| `none` | nothing |

`string-set` on an element sets a named string when the flow reaches it, and `content()` inside it is the element's own text, which only headings and paragraphs have any of. The built-in sheet already sets `chapter` from a section's opening heading, so a running head is one rule:

```css
@page :right {
  @top-center {
    content: string(chapter);
    font-size: 8pt;
    letter-spacing: 0.06em;
  }
}
```

`string()` reads the string as it stood when the page opened rather than as the first element on the page set it, so a chapter opening halfway down a page does not retitle the page it opened on. A string nothing has set yet paints nothing.

A `-center` box is centred on the trim rather than on the content box, because a folio belongs on the page's axis and mirrored margins put the content box off it. `-left` and `-right` align to the content box's edges.

A page the flow put nothing on paints no margin boxes at all, so a page whose only content would be a running head does not get one. `@page :blank` still gives that leaf its trim and margins.

### Folios

`counter(page)` in a margin box paints the folio.

{/* generated: counter-styles */}

`<counter-style>` is `decimal`, `lower-roman`, `upper-roman`, `lower-alpha` and `upper-alpha`.

{/* end generated */}

A number the counter style cannot express falls back to decimal.

`counter-reset: page <integer>` on an element restarts the count. The page that element opens takes that number and the pages after it count on from there:

```css
section.body { counter-reset: page 1 }
```

Blank leaves count. Recto and verso do not follow the folio: which side of the spread a page falls on is where it sits in the sheet, not what is printed on it, so front matter restarting the body at 1 leaves the sides alone.

### Columns

`column-count` and `column-width` divide the page's content box. `column-count` alone takes that many columns. `column-width` alone takes as many columns of at least that width as fit. Declared together, the count is the ceiling on how many the width takes. `column-gap` is the gutter between them, and `normal` is one em of the book's own size.

```css
@page {
  size: a4;
  margin: 20mm;
  column-count: 2;
  column-gap: 18pt;
  column-rule-width: 0.5pt;
  column-rule-style: solid;
}
```

The flow fills the first column to its foot, then the next. Only the last column running out starts a page. A paragraph breaks to the column it is set in, and orphans, widows and `break-inside: avoid` hold inside a column. `break-before: column` and `break-after: column` open the next column rather than the next page.

`column-rule-style: solid` paints a rule down each gutter, `column-rule-width` wide, centred in the gutter and reaching the foot of the columns it divides. The rule takes no width from the columns. A page the flow left in one column paints no rule.

Running heads, folios and margin boxes belong to the page rather than to a column. Dividing the content box leaves them where an undivided page puts them.

## Selectors

{/* generated: elements */}

Element names are the markdown vocabulary: `book`, `section`, `h1`, `h2`, `h3`, `h4`, `h5`, `h6`, `p`, `blockquote`, `hr`, `img`, `code`, `em`, `strong` and `a`.

{/* end generated */}

{/* generated: compounds */}

A compound is `<element>` (`p`), `*` (`section > *`), `.<class>` (`p.epigraph`) or `#<id>` (`#frontispiece`), with any of the pseudo-classes `:first-child`, `:last-child`, `:only-child`, `:nth-child()`, `:nth-last-child()`, `:first-of-type`, `:last-of-type`, `:only-of-type`, `:nth-of-type()`, `:nth-last-of-type()`, `:empty`, `:root`, `:is()`, `:where()`, `:not()` and `:has()`.

{/* end generated */}

{/* generated: combinators */}

Compounds join by the descendant (`section p`), child (`section > p`), next-sibling (`h1 + p`) and subsequent-sibling (`h1 ~ p`) combinators, and selectors list with `,` (`h1, h2`).

{/* end generated */}

```css
h2 + p { text-indent: 0 }
section > p:first-child { text-indent: 0 }
blockquote p:not(:first-child) { text-indent: 1em }
:is(h1, h2, h3) { break-after: avoid }
h1, h2 { text-align: center }
```

There are no attribute or namespace selectors, and no interaction pseudo-classes, because nothing here is interactive.

Text runs are not elements. They take the style of the inline or block around them, and never count towards `:first-child`.

### Classes and ids

A class or an id names one element rather than a kind of them: this image rather than every `img`. An element takes any number of classes and at most one id. Two elements under one id both match, and the second one warns. [The markdown mapping](reference/markdown.mdx) is where a manuscript writes them.

```css
p.epigraph {
  font-style: italic;
  text-indent: 0;
  margin: 2em 4em;
}

#frontispiece {
  margin: 0;
  break-after: page;
}
```

### Pseudo-elements

{/* generated: pseudo-elements */}

The pseudo-elements are `::first-letter` and `::first-line`.

{/* end generated */}

Both cascade over the style of the element they belong to, so a rule that names one starts from that element's own font and size. `::first-letter` is [where a drop cap comes from](#drop-caps), and `::first-line` [sets a paragraph's opening line](#first-lines). Where both fall on the same paragraph, `::first-letter` takes the initial and `::first-line` sets the rest of the line.

## Declarations, values and units

{/* generated: declaration */}

A declaration is `<property>: <value> !important?`.

{/* end generated */}

{/* generated: units */}

Lengths are `pt`, `px`, `pc`, `in`, `cm`, `mm`, `q`, `em` and `rem`, and everything computes to points.

{/* end generated */}

`em` in `font-size` is a multiple of the parent's size and elsewhere of the element's own. `rem` is always a multiple of the root's.

Colours are a CSS colour name, `#rgb`, `#rrggbb`, or `rgb()` over numbers or percentages. There is no alpha channel.

## Text

These properties inherit, so a value on `book` or `section` reaches the prose under it and a rule on `h2` beats what the heading inherited.

### Line breaking and justification

Lines break by total fit over the whole paragraph rather than one line at a time: every set of breaks is costed by how far each line falls from the measure, cubed, and the cheapest set wins. A word that would fill one line stays where it is when taking it leaves a hole in the next.

`text-align: justify` opens the space between words to reach the measure exactly, on every line but the last. `text-justify: inter-character` lets the space between letters change as well; the default does not. `left`, `right` and `center` break the same way and sit where the alignment puts them. `start` is `left` and `end` is `right`.

### Hyphenation

`hyphens: auto` adds syllable boundaries to the breaks a line may take, each charged for the hyphen it leaves and for coming after another one. No more than two lines in a row end hyphenated. `none` and `manual` add no syllable breaks.

The syllables are the ones the book's language has. `extra["language"]` in the [metadata](reference/markdown.mdx) names it, as a BCP 47 tag read by its primary subtag: `fr-CA` is French. A book that declares no language breaks by English. A language with no patterns leaves every word whole, and a diagnostic names the tag. The tag is the book's, so one book is set in one language.

```css
book {
  text-align: justify;
  text-justify: inter-word;
  hyphens: auto;
  hanging-punctuation: first allow-end last;
}
```

### Small caps, tracking and case

`font-variant-caps: small-caps` takes the face's `smcp` feature. A face without one draws its lowercase as capitals at four-fifths of the size, and a diagnostic names it, so an author can pick a face that has them.

`letter-spacing` is advance added between the glyphs of a run, and the total-fit pass measures it like any other width. Nothing is added after a line's last glyph, so a tracked title centres on its own letters rather than on the space after them.

`text-transform` changes the characters that are shaped, not the text a painter reads back: a PDF's text extraction, a search over it and copy and paste all return the manuscript. `capitalize` raises the letter a word opens with, where a word continues through letters, digits and the apostrophe inside one.

```css
h2 {
  font-variant-caps: small-caps;
  letter-spacing: 0.08em;
  text-align: center;
  font-weight: normal;
}
```

### Colour

`color` is the ink a run is set in, and it inherits.

```css
book { color: #241f1c }
h2 { color: rgb(140, 30, 30) }
.epigraph { color: #6b6257 }
```

The preview and the PDF fill from the same field on the run.

### Hanging punctuation

`hanging-punctuation` lets a mark sit outside the measure so the edge of the text block reads straight. A full stop or a comma at the end of a line leaves a hole in the margin, and hanging it closes the hole.

| value | hangs |
|---|---|
| `first` | an opening quotation mark or bracket, back into the margin the line starts at |
| `force-end` | a closing mark past the measure, on every line |
| `allow-end` | a closing mark, only where that is what makes the line fit |
| `last` | the mark a paragraph ends on |

How far a mark hangs depends on the mark: most of a full stop or a comma, less of a colon, and none of a letter.

## Blocks

These do not inherit. A block is a paragraph, a heading, a quotation, an image or a thematic break.

### Margins, borders and padding

A block has a margin, a border and padding around its content, and a background behind them.

```css
blockquote {
  margin: 1em 2em;
  padding: 0.5em 1em;
  border-left: 2pt solid #b9b0a2;
  background-color: #f4f1ea;
}
```

`margin` and `padding` take a one-to-four value shorthand and a longhand per edge. `border` takes a width, a style and a colour in any order, and `border-top`, `border-right`, `border-bottom` and `border-left` take the same three for one edge. `border-width`, `border-style` and `border-color` each set one of the three across all four edges, with the one-to-four value shorthand `margin` uses. `border-style` is `none` or `solid`.

The border and the padding on the left and right narrow the measure and move the leading edge in by what they take. The ones on the top and bottom take height in the flow, and the margins on either side of them no longer collapse: a top border on a blockquote sits between the quote's own top margin and its first paragraph's, and both take space.

`background-color` fills the border box, with the border over it. Neither inherits.

Where two edges of different colours meet, the corner goes to the horizontal one rather than mitring, and there are no rounded corners.

### Breaking across pages

`break-before` and `break-after` open a page or a column before or after a block. `break-inside: avoid` moves a block whole rather than split it.

| value | |
|---|---|
| `auto` | break wherever the flow falls |
| `avoid`, `avoid-page`, `avoid-column` | do not break here |
| `page`, `always` | the next page |
| `left`, `verso` | the next verso |
| `right`, `recto` | the next recto |
| `column` | the next column |

`orphans` and `widows` bound where a paragraph may be cut: fewer than `orphans + widows` lines and it moves whole too. Where no allowed break remains, the page ends anyway.

```css
section { break-before: recto }
h2 { break-after: avoid }
blockquote { break-inside: avoid }

p {
  orphans: 2;
  widows: 3;
}
```

A page break through a block splits its box, and `box-decoration-break` settles the two edges the break made. `slice`, the initial value, draws the block as one box and cuts it, leaving both open. `clone` closes each piece on all four edges. Neither repeats the padding, which belongs to the block's own top and bottom.

### Ornaments

`content` sets the text of an empty element, which in the markdown vocabulary is the thematic break. The built-in sheet sets a floral heart, and another string replaces it.

```css
hr {
  content: "* * *";
  text-align: center;
  margin: 1.5em 0;
}
```

## Chapter openings

### Drop caps

`initial-letter` on `::first-letter` sinks the initial into the paragraph. The initial is sized from the number of lines rather than from `font-size`: its cap height spans that many lines, so its baseline lands on the last of them and its top on the first line's cap height. The lines beside it break to the measure it leaves.

```css
h2 + p {
  text-indent: 0;
}

h2 + p::first-letter {
  initial-letter: 3;
  font-family: "Author Display", serif;
}
```

### First lines

{/* generated: first-line-properties */}

`::first-line` takes `color`, `font-size`, `font-variant-caps`, `letter-spacing` and `text-transform`, and nothing else.

{/* end generated */}

A declaration outside that set warns naming the property and is dropped.

`::first-line` reaches the paragraph's first line rather than the page's, so a paragraph broken across a page boundary is styled on its opening line and nowhere else.

```css
h2 + p::first-line {
  font-variant-caps: small-caps;
  letter-spacing: 0.06em;
}
```

Which words the line holds depends on the style over it. `letter-spacing`, `font-variant-caps`, `text-transform` and `font-size` change the width of the text, and the width moves where the line breaks. The style covers the words the line comes to hold, wherever that break lands. `font-size` grows the line around the baseline the paragraph shares. `color` is paint alone, and the lines break the same with it or without it.

## Fonts

`@font-face` registers a face under the family a selector names it by.

```css
@font-face {
  font-family: "Author Serif";
  src: url("faces/author.ttf") format("truetype"), local("Author Serif");
  font-style: normal;
  font-weight: 400;
}

book {
  font-family: "Author Serif", serif;
}
```

{/* generated: font-face */}

| descriptor | values | example |
|---|---|---|
| `font-family` | `<family-name>` | `font-family: "Author Serif"` |
| `font-style` | `normal \| italic \| oblique` | `font-style: italic` |
| `font-weight` | `normal \| bold \| <number [1,1000]>` | `font-weight: bold` |
| `src` | `[ <url> format(<string>)? \| local(<string>) ]#` | `src: url(fonts/serif.otf)` |

{/* end generated */}

The string in `url()` is handed to the loader unchanged, and does not have to be a real URL. A face that resolves registers under the family the sheet declared, not the one inside the file. A face that resolves nowhere warns, and text falls back to the next family in the list.

`font-family` is tried in order and the first registered family answers. Within it, slope decides before weight. No slope or weight is synthesised. [Fonts](library/fonts.md) has the full matching rules and how variable files register.

## The built-in sheet

Every rule an author sheet cascades over, in the vocabulary this page describes.

{/* generated: defaults */}

```css
/* The user-agent stylesheet: fleuron's defaults, as CSS.
   A trade paperback — 6x9in, mirrored margins, a folio in the bottom
   margin — because that is the book most manuscripts become. Author
   CSS cascades over every rule here. */

book {
  font-family: serif;
  font-size: 11pt;
  line-height: 1.4;
  text-align: left;
  hyphens: none;
  orphans: 2;
  widows: 2;
}

/* A chapter opens on a right-hand page, and its pages are named so
   that @page can tell an opening from a continuation. */
section {
  page: chapter;
  break-before: recto;
}

h1, h2, h3, h4, h5, h6 {
  font-size: 18pt;
  break-after: avoid;
}

/* Prose tells one paragraph from the next with an indent rather than
   a blank line, so the indent belongs to a paragraph that follows
   another one. A paragraph that opens a chapter or a quotation, or
   picks the prose up again after a heading, a scene break or an
   illustration, has nothing above it to be told apart from, and sets
   flush. */
p + p {
  text-indent: 1.2em;
}

/* A quotation is set narrower than the measure and off from the
   prose around it, and stays together across a page turn as far as
   its own orphans and widows allow. */
blockquote {
  margin: 1em 2em;
}

/* A scene break is an ornament centred in the measure. It belongs
   between paragraphs, so it never opens or closes a page: what would
   read as a stray mark at a page turn moves with the prose. */
hr {
  content: "\2766";
  text-align: center;
  margin: 1em 0;
  break-before: avoid;
  break-after: avoid;
}

/* A section's opening heading is its chapter title, and travels as a
   named string so a running head can pick it up with
   string(chapter). Where that shows is the author's business; that
   there is something to show is not. */
section > :is(h1, h2, h3, h4, h5, h6):first-child {
  string-set: chapter content();
}

em { font-style: italic }
strong { font-weight: bold }
code { font-family: monospace }

@page {
  size: 432pt 648pt;
  margin: 54pt 42pt 54pt 54pt;
  @bottom-center {
    content: counter(page);
    font-size: 9pt;
    line-height: 1.4;
  }
}

/* Margins mirror across the spread: the wider one is always the
   spine. */
@page :left {
  margin-left: 42pt;
  margin-right: 54pt;
}

@page :right {
  margin-left: 54pt;
  margin-right: 42pt;
}

/* A chapter's opening page counts but does not show its folio. A
   blank inserted to square the sheet counts too, and paints nothing
   at all: that rule is the engine's, not this sheet's. */
@page chapter:first {
  @bottom-center { content: none }
}
```

## Not in the subset

Floats, tables, grid, flexbox, transforms, media queries, custom properties, counters other than `page`, `counter-increment`, `font-variant` beyond `font-variant-caps: small-caps`, and generated content beyond page margin boxes, `string-set`, and `content` on an empty element.

The box model is missing the `background` shorthand and every background property but `background-color`, the border longhands that name both an edge and a value, such as `border-top-width`, `border-radius`, and a border, padding or background on an inline element or on `@page`.

Columns are missing `column-fill`, so the last page fills its columns in order and stops short rather than balancing them; `column-rule-color`, so a rule paints in the ink the book is set in; and `column-span`, so nothing spans the full measure with columns above and below it. The `columns` and `column-rule` shorthands are missing too, and columns on an element: `@page` is where the box divides.

Each is reported per declaration, at the line and column it was written at, and the rest of the sheet still applies. [Diagnostics](library/diagnostics.mdx) is where a warning is read. These are properties the engine does not support yet, not properties it rules out.

## The subset as data

`fleuron --css-subset` writes this page's vocabulary as JSON: every selector, property, value and at-rule, with the engine version it came from. A host that embeds the engine pins the file for that version and drives its own editor from it. The same description is `fleuron::style::subset::Subset::describe()` in the library, and the tables on this page are rendered from it.
